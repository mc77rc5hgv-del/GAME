# Avito monitor → Telegram

Опрашивает заданные поисковые URL Avito (со своими фильтрами) и присылает
новые подходящие объявления в Telegram.

## ⚠️ Важное ограничение

Avito закрывает трафик с дата-центровых IP антиботом Qrator. В облачном
рантайме (в том числе GitHub Actions) запросы могут стабильно получать
`429` и не доходить до реальных данных — это ограничение сети/IP, а не
скрипта. Если так и происходит:

- вы получите в Telegram предупреждение о блокировке (скрипт не падает
  молча — после нескольких неудачных попыток подряд шлёт алерт, не чаще
  раза в 6 часов);
- рабочая альтернатива — гонять `monitor.py` по расписанию (cron /
  Планировщик заданий) на своём компьютере или домашнем сервере, где IP
  не в чёрных списках;
- либо завести self-hosted GitHub Actions runner на своей машине и
  указать `runs-on: self-hosted` в workflow.

## Настройка

1. Создайте бота в Telegram через [@BotFather](https://t.me/BotFather),
   получите `TELEGRAM_BOT_TOKEN`.
2. Узнайте свой `chat_id` (например, напишите боту и откройте
   `https://api.telegram.org/bot<TOKEN>/getUpdates`, либо через
   [@userinfobot](https://t.me/userinfobot)).
3. Скопируйте `config.example.json` в `config.json` и впишите свои
   фильтры — это обычные ссылки на поиск Avito с уже применёнными
   фильтрами (город, цена, категория и т.д.), просто скопируйте URL из
   адресной строки после того как настроите поиск на сайте:

   ```json
   {
     "filters": [
       {"name": "iphone-moskva", "url": "https://www.avito.ru/moskva?q=iphone&pmin=10000&pmax=50000"}
     ]
   }
   ```

4. **Если запускаете через GitHub Actions**: добавьте в репозитории
   Settings → Secrets and variables → Actions два секрета —
   `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Workflow
   `.github/workflows/avito-monitor.yml` крутится каждые 15 минут.
   Учтите: расписания GitHub Actions запускаются только с дефолтной
   ветки репозитория и отключаются автоматически после ~60 дней без
   активности в репозитории — если это ваш случай, зайдите и сделайте
   любой коммит или перезапустите workflow вручную (`workflow_dispatch`).

5. **Если запускаете локально**:

   ```bash
   pip install -r requirements.txt
   export TELEGRAM_BOT_TOKEN=...
   export TELEGRAM_CHAT_ID=...
   python monitor.py
   ```

   и добавьте это в cron (Linux/macOS) или Планировщик заданий (Windows)
   на нужный интервал, например каждые 5–15 минут.

## Как это работает

- Первый запуск для каждого фильтра только запоминает текущие
  объявления (baseline) — уведомлений не будет, чтобы не засыпать вас
  всей историей сразу.
- На последующих запусках в Telegram уходят только объявления, которых
  не было в прошлый раз.
- Состояние (уже виденные id объявлений) хранится в `state/<имя
  фильтра>.json`.
- Парсинг сначала пробует структурированные данные (`ld+json` на
  странице), при неудаче — HTML-разметку по `data-marker`. Avito
  периодически меняет вёрстку — если объявления перестали парситься,
  скорее всего придётся поправить `parse_via_data_marker` в
  `monitor.py`.
